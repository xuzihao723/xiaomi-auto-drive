项目技术流程

四个模块，一条可追溯的链路。

代码按技术职责组织，每个阶段连接实现、配置、校验与已发布结果。

  1. 01 / SIMULATION

    可控仿真环境

    Windows CARLA Server 与 WSL2 Client，完成交通流生成与人工驾驶验证。

    查看仿真模块 →
  2. 02 / DATA

    对齐传感器数据

    同步 RGB、LiDAR 与 Actor 标签，转换 KITTI，并自动校验数据完整性。

    查看数据管线 →
  3. 03 / DETECTION

    识别道路目标

    类别专长 YOLOv8 检测车辆、行人、交通灯与标志，保留分组评估和标签复核证据。

    查看检测模块 →
  4. 04 / SEGMENTATION

    提取道路几何

    U-Net 分割、夜间适配、可行驶区域提取与车道线拟合，并集成目标检测结果。

    查看分割模块 →

关键工程决策

展示结果，也解释结果。

  • 避免连续帧跨划分泄漏

    场景 / 连续帧块分组与缓冲帧用于控制泄漏，公开校验记录显示组重叠与精确图像重叠均为零。

    查看划分校验 ↗

  • 让不同类别使用专长模型

    道路参与者与交通控制目标由不同检测器负责，同一 test 下 mAP50 从 0.473 提升至 0.704。

    查看检测指标 ↗

  • 同时报告适配收益与权衡

    夜间 mIoU 从 0.004 提升至 0.778；暴雨 mIoU 从 0.659 变为 0.637。两种变化均保留在记录中。

    查看适配前后对比 ↗
