The project workflow

Four modules. One traceable pipeline.

Code is organized by responsibility. Each stage connects its implementation with configuration, validation and published evidence.

  1. 01 / SIMULATION

    A controlled world

    Windows CARLA Server and a WSL2 client, with traffic generation and manual-driving validation.

    Explore simulation →
  2. 02 / DATA

    Aligned sensor data

    Synchronized RGB, LiDAR and actor labels. KITTI conversion with automated integrity checks.

    Explore data pipeline →
  3. 03 / DETECTION

    Road objects

    Specialized YOLOv8 models for cars, pedestrians, traffic lights and signs. Grouped evaluation and label review.

    Explore detection →
  4. 04 / SEGMENTATION

    Road geometry

    U-Net segmentation, night adaptation, drivable-area extraction and lane fitting, integrated with detections.

    Explore segmentation →

Engineering decisions

Results with an explanation.

  • Keep neighboring frames out of opposing splits

    Scene/frame-block grouping and buffer frames address leakage from continuous sequences. Published checks record zero group and exact-image overlap.

    Inspect split validation ↗

  • Give object classes specialized models

    Road users and traffic-control objects use separate detectors. Same-test mAP50 improves from 0.473 to 0.704.

    Inspect detection metrics ↗

  • Report adaptation gains and tradeoffs

    Night mIoU improves from 0.004 to 0.778; heavy-rain mIoU changes from 0.659 to 0.637. Both are kept in the record.

    Inspect before / after ↗
